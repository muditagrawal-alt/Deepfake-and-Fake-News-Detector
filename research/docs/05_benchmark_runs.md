# 5. Benchmark run record

One entry per run of the v3 engine: what ran, on which engine version and hardware, what went wrong while it ran, and what it showed. Metrics are copied from `results/benchmark_summary.csv` (regenerated by `scripts/build_results.py`); per-item outputs are in `runs/<run>.csv` and `runs/<run>.jsonl`; errors hit during a run, including ones later resolved by a retry, are in `runs/<run>.errors.csv` (runs from 2026-09-29 10:00 IST on) or the driver log `runs/_v3_<backend>.log`.

Conventions: an item that fails (provider error, timeout, network) is recorded as an error and re-run; it is never scored. A run is valid when ≤ 5% of items failed; the driver keeps resuming until none did. Engine versions are identified by the git tree hash of `backend/detector` (`engine_tree` in each manifest).

### R0 — in-house images, v3.0, Gemini 3.5 Flash-Lite (pilot, not reported)
- **When:** 2026-09-28 23:36 – 2026-09-29 00:10 IST. **Status:** stopped at 23/50 when v3.1 was frozen, so every reported number comes from one engine. Kept in `runs/pilot/`.

### R1 — in-house images, original inputs
- **Config:** v3.1 (`76848a6`), Gemini 3.5 Flash-Lite, pinned; retrieval open; DuckDuckGo. Mac on battery, Low Power Mode on (affects latency only).
- **Errors:** 1 ReadTimeout (item 48, a fake image; ~129 s), resolved on attempt 2.
- **Result:** accuracy **0.880** [0.762, 0.944]; FAKE recall 0.84, REAL recall 0.92; macro-F1 0.880; AUC 0.898. v1 on the same items 0.86 (McNemar p = 1.00).
- **Failure modes** (`results/error_analysis.csv`): 4 fakes missed with no anomaly observed; 2 real photos called fake because unusual content was read as artefacts (a basketball court's lines, a bookshelf photographed from an odd angle). Two of the missed fakes are AI recreations of real events (a Trump–Epstein photograph, a cricket match): retrieval found that the real event and a real photograph exist, and the model concluded the image was authentic. → **I-6**.

### R2 — in-house videos, original inputs
- **Config:** as R1.
- **Errors:** 4 × HTTP 503 "high demand", 2 × ReadError, 2 × ReadTimeout across attempts 1–3 (all on real videos); resolved on attempt 4. One item took 846 s before failing.
- **Result:** accuracy **0.933** [0.787, 0.982]; FAKE recall 0.87, REAL recall 1.00; AUC 0.956. v1 (reproduced) 1.00 (p = 0.50).
- **Finding:** the 13 fakes with a valid C2PA `trainedAlgorithmicMedia` manifest were all detected (0.99–1.0); the 2 fakes without one were called real at 0.95. Six of the 13 detected fakes had no anomaly recorded. On original files the result equals the C2PA-only baseline (0.933). → **I-7**.

### R3 — in-house images, resolution control (`img_norm512`)
- **Config:** as R1; every image 512 px longest side, JPEG q90, EXIF removed.
- **Errors:** 2 × ReadTimeout; 1 × ConnectError (DNS failure while the Mac was asleep overnight). The run stalled from 01:56 to ~09:00 IST while the machine slept; the driver was restarted under `caffeinate -i` and resumed the 19 completed items.
- **Result:** accuracy **0.820** [0.692, 0.902]; FAKE recall 0.72, REAL recall 0.92; AUC 0.886. vs R1: −0.06, 95% CI [−0.16, +0.04], p = 0.45. All trivial baselines are at chance on this input.

### R4 — in-house videos, metadata stripped (`vid_strip`)

### R10 — Round 1, FakeNewsNet-PolitiFact test (102), with web search — complete 2026-10-15 23:03 IST
- **Engine** v3.1.4, Gemini 3.5 Flash-Lite, free tier (payment still processing), 4 workers.
- **Errors:** 5 items refused by the free-tier per-minute quota on the first pass; re-run on attempt 2; final 0 errors.
- **Result:** accuracy **0.804** [0.716, 0.869]; macro-F1 **0.710** [0.601, 0.815]; AUC **0.794**; FAKE recall 0.41, REAL recall 0.96.
- **vs published zero-shot (LLaVA-1.5-13B, MM-Soc):** macro-F1 0.749, accuracy 0.827, AUC 0.721 — all **inconclusive** (the reference lies inside our intervals). Below the supervised DeBERTa-v3-large (0.952). Above random (0.471).
- **Observation for the paper (not used for any change):** the engine is conservative — it rarely calls a real article fake (REAL recall 0.96) but misses most fakes (FAKE recall 0.41), because without contradicting evidence it defaults to REAL or UNCERTAIN. Its ranking is good (AUC 0.794). The pre-registered learned scorer (Round 2) sets the decision threshold from training items.

### Round 1 — started 2026-10-15 (engine v3.1.4, tree `9d9b840`, Gemini 3.5 Flash-Lite, pinned)
- **Queue:** FakeNewsNet-PolitiFact test (102, with web search) → LIAR test300 → GossipCop test300 → PolitiFact test without web search; 4 items in parallel; fact-check sites excluded; runs labelled `__round1__`; spend cap ₹1,000 on the shared ledger (estimated at paid-tier prices, so an upper bound while calls are still free).
- **Tier:** the account's ₹1,000 prepayment was still processing, so the run began on the **free tier**. Google's 429 message names the quota `generate_content_free_tier_requests`, limit 15 per minute, which also serves as the tracker: when those refusals stop and throughput exceeds 15 requests per minute, the paid tier is active. Refused calls are retried; items that exhaust retries are re-run by `--resume`, never scored.
- **Enhancement check** (v3.1.4 vs v3.2.0 on the news development sets) was started in parallel and **paused after one item**, because the three processes shared the 15-per-minute free limit; it restarts on the paid tier.
- **Full test sets:** LIAR test (1,283) and GossipCop test (2,672) are queued to extend the Round 1 subsets with `--seed-from` (no item is run twice). They are capped at ₹320 on the ledger so the reserve for FaceForensics++, the enhancement check, the scorer's training items and Round 2 (~₹690) is kept; the cap is raised when the $40 Developer Program credits are claimed.
- **FaceForensics++** runs only on the paid tier (dataset terms).

### Paper run plan (2026-10-15)
Chosen by the author: fixed subsets, two rounds. **Round 1** = engine v3.1.4 on FakeNewsNet-PolitiFact test (102, with and without web search), FakeNewsNet-GossipCop `test300`, LIAR `test300`, FaceForensics++ c23 `test200`. Then enhancements developed on development items only (v3.2 and anything the development runs show), then **Round 2** = the enhanced engine on the same test items. Runs are labelled `__round1__` / `__round2__`; every manifest records `engine_version`, `round`, cost in rupees, and the shared spend ledger total. Budget: ₹1,000 prepaid on the AI Studio account (auto-reload off), plus up to $40 of Google Developer Program credits if they can be claimed; the harness stops starting paid items at `SPEND_CAP_INR` (default ₹1,000).

**Measured cost (cost check, 10 development items, free tier, `runs/cost_check/`):** FakeNewsNet article + image 6,771 input / 1,051 output tokens, ₹0.45 per item, 50 s; LIAR statement 2,909 / 814 tokens, ₹0.28 per item, 28 s; no thinking tokens. Projected: one subset round ≈ ₹380, both rounds plus the development check ≈ ₹850.

**Existing tools on FaceForensics++ c23 test200** (`runs/ffpp_c23__test200__tool__*`): dima806/deepfake_vs_real_image_detection 0.505 (FAKE recall 0.25, REAL 0.76); prithivMLmods/Deep-Fake-Detector-v2-Model 0.530 (FAKE 0.71, REAL 0.35).
